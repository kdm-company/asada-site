# ネームサーバー切り替え後にやること

お客さんからネームサーバー変更の連絡が来たら、上から順に進める。

## 1. 切り替わったかを確かめる
- [ ] `dig NS asada-iws.com +short` が `fred.ns.cloudflare.com` と `lucy.ns.cloudflare.com` を返す
- [ ] Cloudflare の asada-iws.com の画面で「I updated my nameservers」を押す（有効化の確認が早まる）
- [ ] Cloudflare の asada-iws.com が「Active（有効）」になっている（届くメールでも通知される）
- [ ] この時点では、まだ旧サイト（WADAX）が表示されていれば正常

## 2. メールが止まっていないかを確かめる（最優先）
- [ ] `dig MX asada-iws.com +short` が `10 sva106.wadax-sv.jp.` を返す
- [ ] `dig A mail.asada-iws.com +short` が `153.123.7.87` を返す
- [ ] SPF・DMARC・DKIM（`default._domainkey`）・`_domainkey` の TXT が引ける（値は `DNSレコード控え.md`）
- [ ] お客さんに送受信を確かめてもらう（当日と翌日）

## 3. 新サイトに切り替える
- [ ] Cloudflare の DNS から、ルートの A（153.123.7.87）と `www` の CNAME を消す（**mail の A は消さない**）
- [ ] `wrangler.jsonc` に次を足して `npx wrangler@4 deploy`（カスタムドメインの DNS は自動で作られる）
  ```jsonc
  "routes": [
    { "pattern": "asada-iws.com", "custom_domain": true },
    { "pattern": "www.asada-iws.com", "custom_domain": true }
  ]
  ```
- [ ] `www.asada-iws.com` → `https://asada-iws.com` へ 301 転送するルールを作る（Rules → Redirect Rules）
- [ ] SSL/TLS の「Always Use HTTPS」をオンにする

## 4. https で開けるか確かめる
- [ ] `https://asada-iws.com/` と `https://www.asada-iws.com/` が開く（www はルートへ転送）
- [ ] `http://asada-iws.com/` が https へ転送される
- [ ] 旧サイトの URL が新ページへ転送される（例：`/business/duct/` → `/service/#duct`、`/company/recruit/` → `/recruit/`、`/case/...` → `/works/`）
- [ ] 存在しない URL で 404 ページが出る
- [ ] PC とスマホ（幅375px）で全ページを見る

## 5. 検索エンジンに載せる設定に戻す
- [ ] 全ページの `<meta name='robots' content='noindex, nofollow' />` を消す
- [ ] `public/_headers` の X-Robots-Tag の行を消す（ファイルごと消してよい）
- [ ] `public/robots.txt` と `public/sitemap.xml` を置く
- [ ] 各ページに `<link rel="canonical">` と `og:url` を本番 URL で入れる
- [ ] `og:image` を絶対 URL にする（`https://asada-iws.com/assets/images/ogp.jpg`）
- [ ] デプロイして、`curl -sI https://asada-iws.com/` に `x-robots-tag` が出ないことを確かめる
- [ ] Google Search Console にドメインを登録し、サイトマップを送信する

## 6. 中身の仕上げ
- [ ] 「ホームページをリニューアルいたしました」の日付（2026.08.22）を実際の公開日に直す
      （記事本文・新着一覧・カテゴリ／月別一覧・各サイドバー・トップのティッカーと新着一覧）
- [ ] GitHub の kdm-company/asada-site に `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID`（`ae8ce5f2d1f4a6b0613960cffe92a74a`）を登録し、push で自動公開されるようにする
- [ ] Notion「浅田｜会社概要・沿革」の「公式サイトは https 未対応」の記述と、note 署名の URL を https に更新する

## 7. 旧サーバーの扱い（お客さんと相談）
- WADAX はメールで使い続けるので、契約は解約しない
- WADAX 上の旧 WordPress サイトは、新サイトの公開を確認したあとに止めるかどうかをお客さんと決める
